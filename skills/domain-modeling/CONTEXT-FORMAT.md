# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{用一两句话说明该上下文是什么，以及为什么存在。}

## 领域术语

**订单（Order）**：
{用一两句话定义该术语。}
_避免使用_：购买、交易

**发票（Invoice）**：
交付后向客户发送的付款请求。
_避免使用_：账单、付款申请

**客户（Customer）**：
下订单的个人或组织。
_避免使用_：委托方、买家、账户
```

## 规则

- **明确选定术语。** 同一概念有多个称呼时，选定最合适的一个，其余列入“避免使用”。
- **定义简短。** 最多一两句话，说明它是什么，而不是它做什么。
- **只包含本项目上下文特有的术语。** 超时、错误类型、工具模式等通用编程概念，即使经常使用，也不属于词汇表。添加前自行判断它是领域概念还是通用编程概念，只保留前者。
- **按需分组。** 术语自然形成不同类别时使用小标题；属于同一领域时，平铺列表即可。

## 单上下文与多上下文仓库

**单上下文（多数仓库）**：根目录放置一个 `CONTEXT.md`。

**多上下文**：根目录的 `CONTEXT-MAP.md` 列出各上下文、位置及关系：

```md
# 上下文映射

## 上下文

- [订单](./src/ordering/CONTEXT.md)：接收并跟踪客户订单。
- [计费](./src/billing/CONTEXT.md)：生成发票并处理付款。
- [履约](./src/fulfillment/CONTEXT.md)：管理仓库拣货和发货。

## 关系

- **订单 → 履约**：订单上下文发出 `OrderPlaced` 事件，履约上下文消费该事件并开始拣货。
- **履约 → 计费**：履约上下文发出 `ShipmentDispatched` 事件，计费上下文消费该事件并生成发票。
- **订单 ↔ 计费**：共享 `CustomerId` 和 `Money` 类型。
```

根据已有文件判断结构：

- 存在 `CONTEXT-MAP.md` 时，读取它以定位上下文。
- 只有根目录 `CONTEXT.md` 时，按单上下文处理。
- 两者都不存在时，第一个术语确定后再创建根目录 `CONTEXT.md`。

存在多个上下文时，判断当前话题属于哪一个；无法确定时再询问。
