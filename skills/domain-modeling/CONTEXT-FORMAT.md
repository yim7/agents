# CONTEXT.md 格式

## 结构

```md
# {上下文名称}

{一两句话说明这个上下文是什么、为什么存在。}

## 术语

**订单（Order）**：
{一两句话定义这个术语。}
_避免_：购买、交易

**发票（Invoice）**：
交付后发给客户的付款请求。
_避免_：账单、付款请求

**客户（Customer）**：
下订单的个人或组织。
_避免_：用户、买家、账户
```

## 规则

- **明确取舍。** 同一概念有多个叫法时，选定最好的一个，其余列在 `_避免_` 下。
- **定义简短。** 最多一两句，说明它**是什么**，而不是它做什么。
- **只收录本项目特有的概念。** 超时、错误类型、工具函数这类通用编程概念，即使项目大量使用也不收录。
- **自然成簇时用小标题分组**；所有术语属于同一领域时，平铺即可。
- 括号中写代码里使用的名称，方便在代码中搜索。

## 单上下文与多上下文

**单上下文（多数仓库）：** 根目录一个 `CONTEXT.md`。

**多上下文：** 根目录的 `CONTEXT-MAP.md` 列出各上下文的位置及相互关系：

```md
# Context Map

## 上下文

- [订购](./src/ordering/CONTEXT.md)：接收并跟踪客户订单
- [计费](./src/billing/CONTEXT.md)：生成发票并处理付款

## 关系

- **订购 → 计费**：订购发出 `OrderPlaced` 事件，计费消费它来生成发票
```
