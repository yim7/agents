# 规格结构

按实际信息裁剪，没有内容的章节直接省略。

```markdown
# <本次工作>

## 目标与背景
用户要解决什么问题，现状如何。

## 本期范围与行为
本期包含什么、明确不包含什么；关键的正常、边界和失败场景下的预期行为。

## 已确认决定
必须保持的契约，以及已接受的实现和验证取舍。

## 验收
用哪些可观察的结果判断完成，需要什么验证环境。

## 后续事项与未决问题
分开列出；未决问题写明影响哪部分。

## 依据
相关的 spec、CONTEXT.md、ADR、接口、原型或代码位置，用链接引用。
```

用户只确认了目标、尚未选定实现时，在“未决问题”里如实写明。
