# 规格参考结构

仅在没有合适的现有格式时采用，并按实际信息裁剪。以下是待填写的结构，不是项目事实；无内容的章节不保留，不要求固定用户故事数量。

```markdown
# <本次工作>

## 目标与背景
用户要解决什么，现状与依据是什么。

## 本次范围与行为
本次包含什么、明确不包含什么；重要正常、边界和失败场景的预期。

## 约束与已确认决定
必须保持的契约，以及已接受的实现／验证取舍；引用依据与适用范围。

## 验收
通过哪些可观察结果判断完成；需要的验证环境与尚不具备的条件。

## 后续与未决
后续设想和未决问题分别记录，说明影响，不默认加入本次范围。

## 相关依据
已有规格、领域文档、接口、ADR、原型或代码位置；避免复制全文。
```

用户只确认目标、尚未决定实现时，保留这个状态，不借模板替用户选方案。引用源包含建议或旧版本时标清性质，不给推断盖上“已确认”。
