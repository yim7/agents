# 结构决策

只解决当前任务中的未决结构选择。已有决定仍适用时直接沿用；发现反证时说明需要调整的依据。

## 决策依据

核对相关代码、调用方和已确认记录。把项目硬约束、当前实现事实、默认偏好和新的建议区分开；不能因为现状如此就认定它不可改变，也不能把设想的理想架构当成既有约束。

保留现有结构、拆分职责、引入类型、合并逻辑或局部重复，都是候选手段。根据当前职责、变化关系、依赖和验证成本判断，不预设某种代码形态更优。不为尚无依据的未来需求设计通用机制，也不为减少本次 diff 延续已经暴露的问题。

存在真实取舍时比较合理方案，并考虑改变现状的成本；不凑固定数量的备选方案。最终结构与迁移路径分别判断，允许有必要且有退出条件的过渡方案。

## 需要交付的结论

用与问题规模相称的篇幅说明：解决哪个选择、依据哪些约束、采用什么方案及主要代价，以及实现或验证所需的边界。只覆盖与该选择有关的内容。

需要跨任务保存的决定写回现有 Spec、任务或设计记录；普通可逆的实现细节不另建文档，不复制已有规格。不确定事项保持为不确定，不冒充用户已确认的决定。

决定足以支持当前工作后，回到原任务；本技能不增加审批步骤，也不扩展实现范围。
