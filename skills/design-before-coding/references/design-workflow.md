# 设计流程

## 何时介入设计

以下变化存在未决结构问题时，先补齐相关设计：

- 任务会改变公共或半公共接口
- 任务会引入新模块或新抽象
- 任务需要拆分责任
- 当前代码已经显得纠缠、重复或难以推理

只处理影响当前工作的未决选择；已有设计直接沿用。设计思考不等于等待用户确认，不阻止无关工作继续推进。

## 阅读当前形状

提出方案前先识别：

- 现有抽象
- 当前模块边界
- 每份重要知识由谁拥有
- 已经出现了哪些复杂度信号

当本地代码结构很重要时，不要脱离代码空想设计。

## 比较设计方向

对每个合理方向追问：

- 接口更简单还是更复杂？
- 隐藏了更多知识，还是泄漏了更多知识？
- 未来修改成本更低还是更高？
- 特殊情况是被吸收，还是被导出给调用方？
- 这是真正的新抽象，还是只是又加了一层？

偏好能从系统其他部分移除复杂度的方向，即使它需要更多前期思考。

## 编码前必须明确什么

针对当前未决问题，按需说明：

- 主要抽象
- 每个相关模块的边界
- 调用方应该看到的接口
- 每个模块内部隐藏的设计决策
- 边界情况如何处理
- 这个设计让什么变化更容易

如果无法简短、精确地解释设计，说明设计还没有稳定。

## 要避免什么

- 在需要新抽象时先写功能
- 按执行顺序拆分，但让同一份知识跨越多个步骤
- 因为第一版已经存在而保留弱抽象
- 把很少用到的选项暴露给所有调用方

## 退出条件

当前问题相关的以下内容足够明确后，结束设计并回到原工作：

- 抽象可以被清楚命名
- 接口可以被简短描述
- ownership 边界稳定
- 不再有阻塞当前工作的结构选择

将新决定写回已有记录。退出本技能不代表批准开发或跨阶段执行；沿用当前授权，不重复请求确认。
