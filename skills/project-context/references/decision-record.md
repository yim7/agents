# 决策记录参考

用于保存缺少背景就容易被误解、且对后续工作有实际影响的重要选择。沿用已有 ADR 或设计记录体系；普通可逆的实现细节不单独建档。

没有既有位置时可使用 `docs/adr/`，有第一份必要记录时再创建。沿用已有编号；没有编号规则时用 `0001-slug.md` 并接续已有最大编号，不改排旧记录。

```markdown
# 决定标题

背景：需要解决什么问题，哪些约束成立。
决定：已经选择的方案，以及适用范围。
理由：真实的取舍、主要代价和未采纳方案中值得保留的理由。
```

这不是必填表。一段文字足以说明上述内容时，不额外增加章节。没有实际比较或确认的内容不能补写成事实。

重新讨论决定时，明确区分提议与已接受状态；已被替代的记录标明替代关系并引用新决定，保留当时的背景，不静默改写过去。已有文件的状态格式优先，可按需用 `proposed`、`accepted`、`superseded` 等状态。

记录决定不等于替用户批准方案。相关操作约束可在项目指令中简短提示并引用这里，不在多处维护完整理由。
