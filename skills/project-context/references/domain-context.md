# 领域上下文参考

用于维护项目中的共同语言及业务语义。优先使用已有词汇表或领域文档；没有合适位置且确有可复用内容时，才创建 `CONTEXT.md`。

项目有 `CONTEXT-MAP.md` 或其他上下文索引时，沿索引定位当前领域。同一词在不同上下文中可以有不同含义，不为统一词汇抹掉真实差异，也不因项目规模推定必须拆分上下文。

```markdown
# 上下文名称

用简短文字说明该上下文的范围。

## 术语

**术语（代码中使用的名称）**：本项目中的含义。
必要时补充容易混淆的概念、已有别名或一个澄清边界的例子。

## 关系与业务语义

记录已确认的关系或不明显的业务规则；需要详细说明时引用主要记录。
与实现现状不同的预期、尚未决定的问题要明确区分。
```

只记录有项目特定含义或影响理解的概念，不复述一般编程知识。定义应便于辨认和使用，不以固定句数限制必要解释，也不机械禁止所有同义词。

它不承担工作命令、任务清单或整份设计方案。架构选择的理由放入对应设计记录；不能把它们与术语定义混为一谈。
