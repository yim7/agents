# Obsidian 网页精选归档

把 URL 内容保存成 Obsidian 知识笔记：默认保留原文正文，按用户意图切换为中文译文或整理总结，用大模型生成标题、summary 和 tags，图片本地化并只保存被文档引用的图片。

## 流程

1. 确认目标 Obsidian 目录；目录不明确时只问一次。
2. 严格按用户指定范围抓取：主页不跑偏，thread 抓完整，文章抓正文和正文内图片。
3. 先展开长文、折叠内容、thread 后续，再判断价值。
4. 原始数据和媒体先存到当前工作区，便于重跑。
5. 先判断保存模式，再写 Markdown；一条保留内容一篇文档。
6. 最后校验数量、元数据、附件引用和分段结构。

## 保存模式

默认是原文存档：中文内容保留原文正文、分段、列表、URL 和图片位置；只清理平台噪音、修复断行 URL、合并同作者 thread、追加有价值补充，不把正文改写成总结。

用户明确要求“翻译”“译文”“原文翻译”“全文翻译”时进入译文模式：正文按原文顺序逐段处理，保留原有标题、列表、分段和信息点，不改写成综合总结，不额外扩写背景；只在必要时润色中文表达。受版权限制时，改为忠实译介并说明不能逐字全文翻译。

用户明确要求“整理”“总结”“提炼”“改写成笔记”时进入整理模式：理解全文后，用清晰中文重写为知识笔记，可合并重复信息和压缩低价值细节。

## 保留标准

保留：观点、经验、方法、交易/项目/事件复盘、风险提醒、机制解释、有价值的同作者补充。

跳过：普通回复、吐槽、玩笑、炫耀、情绪状态、无上下文纯图、低信息量转发、被更完整内容覆盖的重复观点。

同作者 thread 直接拼成完整文章。回复如果是长文下面的有价值补充，追加到原文下面。外部引用只保留理解观点所需的必要上下文。

## 文档格式

YAML 只保留这些字段和顺序：

```markdown
---
author: "作者名 (@handle)"
published_at: YYYY-MM-DDTHH:MM:SS
source: "https://..."
tags:
  - 标签一
  - 标签二
---
```

元属性保持克制：文件名承担标题，`published_at` 承担时间，`source` 承担原始 URL，summary 放在正文 callout。tags 精炼到 2-4 个。

正文开头：

```markdown
> [!summary] 一句话
> 大模型生成的一句话总结。

正文从这里开始。
```

## 标题和 Summary

标题、summary 和 tags 都由大模型读完全文后生成。

标题：像一篇文章的题名，用“具体对象/事件 + 核心问题”命名，读标题就知道大概在讲什么；可以保留有辨识度的原文关键词，但不要写成口号、谜语或一句压缩摘要。

summary：一句话说明这条内容为什么值得保存，直指作者的判断、经验、复盘结论或风险提醒。

tags：2-3 个，短而可复用，像索引入口而不是标题摘要；每个 tag 不含空格，优先用 `AI`、`Tradefi`、`套利`、`期权` 这种入口词。把 `SellPut`、`BuyCall` 归到 `期权`，把 `跨市场价差` 归到 `套利`；避免 `AI研究`、`TradFi合约` 这类过长标签，也避免“观点”“文章”“项目观察”这类泛标签。

生成 tags 前，先扫描目标 Obsidian 库中已有 YAML tags；如果库根目录有 `标签词表.md`，先读它并优先复用其中的入口词和合并规则。只有现有词表确实覆盖不了新内容时才新增 tag。

## 正文和图片

保留段落、列表、标题、URL 和外链；修复被换行截断的 URL；长文保持可读分段。

社媒图片放在对应文字下面，顺序贴近原帖；文章图片尽量放回原插入位置。图片统一复制到 `附件`，文档中用 `![[附件/filename.ext]]`。只保存被保留文档正式引用的图片，重跑后清理未引用的生成附件。

## 完成前检查

报告：源内容数、写入文档数、跳过回复数、跳过低价值数、追加补充数、复制图片数、目标目录；批量归档后刷新库根目录 `标签词表.md` 的当前使用统计。

确认：附件引用都有本地文件，没有未引用生成附件；元属性克制且不重复；文件名像知识笔记标题；抽样文档保留分段，标题和 summary 是模型理解后写的。
