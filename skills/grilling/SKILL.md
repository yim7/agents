# 需求访谈

持续访谈，直到和用户达成共同理解。把讨论组织成一棵**设计树**：每个决策下挂着依赖它的后续决策。

## 轮次

按轮推进。**frontier** 是前提都已确定的决策：现在就能问、不必猜测尚未得到的答案的问题。每轮问完整个 frontier，每题编号并给出推荐答案，然后等用户回答再进入下一轮。

```
❓ **Q1** - **<问题标题>**：<问题内容，可以多段，可以列出选项>

➡️ <推荐答案及理由>

---

❓ **Q2** - **<问题标题>**：<问题内容>

➡️ <推荐答案及理由>
```

每轮回答都会改写设计树：已定的决策把 frontier 往外推，解锁依赖它们的问题。每轮重新计算 frontier；依赖本轮另一个未决问题的问题，放到后面的轮次。

## 事实与决策

**事实**由你查明。需要代码、文档、文件或工具里的信息时自己去查（可以派子代理），用户只回答决策。查证进行中的问题算作未定前提：只有依赖它的问题等待，其余照常提问。

**决策**归用户：需求、产品行为和关键取舍逐一交给用户。

未来需求同样进入设计树，讨论它对当前方案的影响，并标为后续事项，与本期范围分开。

## 结束

frontier 为空即结束：设计树每个分支都已走过，没有默认的假设。此时汇总已确认决定、本期范围、后续事项和未决问题，请用户确认已达成共同理解，确认后再进入后续工作。

用户随时要求结束访谈、整理文档或开始开发，就立即切换，未问完的问题列为未决事项。
