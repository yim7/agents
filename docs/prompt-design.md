# Prompt 系统设计与本次取舍

本说明描述整个 PR 相对基线 `695f8add8dd31827ecc874ade2c64d9ba9b539f1` 的变更，不是某个增量提交的变更清单，也不是 Agent 每次必读的运行指令。

## 原则

Prompt 和 skill 提供模型无法自行确定的项目事实、个人取舍、真实流程依赖、工具用法和验收要求，不重复一整套软件工程课程。任务表达清楚目标、上下文、约束和验收；已有信息引用即可。

硬约束、默认偏好和针对模型的临时补丁应能区分。用户明确选择的方法在约定范围内执行，但不因一次失败就永久增加全局步骤。减少对实现形态的预设，不减少自主执行责任或验证质量。

## 阶段与工作偏好

前期想充分，开发有边界。Grill Me 用于深入发现模糊和遗漏，不以能写出最小版本为提前结束标准。未来需求可以影响方案讨论，但讨论范围不等于本期实现范围。

文档承接共同理解，不把未决内容补成确认结论。开发使用已确认文档或对话中的当前交付目标，不沿用访谈的逐题等待方式。简单任务不因此增加访谈、文档或审批步骤。

多步开发优先采用曳光弹式迭代，以适合任务的可验证结果推进；产品功能、库、迁移和调查可以有不同产物。这是开发偏好，不是要求所有任务补齐前后端，更不是缩短前期访谈的理由。可执行规则见 [AGENTS.md](../AGENTS.md)。

## 规则归属

| 维护位置 | 职责 |
| --- | --- |
| 用户级 `AGENTS.md` | 跨任务协作、文档交接、开发中新信息处理、权限与安全底线 |
| 项目及模块 `AGENTS.md` | 已核实的入口、命令、契约、局部取舍 |
| `grilling` | 访谈方式、充分探索、退出和交接，不管理退出后的开发 |
| `deliver` | 当前结果的实现、整合、验证和交付 |
| `to-tickets` | 任务粒度、真实依赖、验收与记录方式 |
| 两份设计技能 | 分别形成方案与检查方案，不规定固定的实现形态 |
| 维护说明、示例和测试 | 解释与检验规则，不独立增加运行要求 |

以明确的维护位置避免同一决策出现不一致的规范。允许技能为其特定产物保留必要的简短提示，也允许说明文档和测试复述预期行为；不是要求消除所有语义重复。修改时核对相关用例，不能把少量重复本身判为设计缺陷。

开发中新信息的分类与授权边界以全局约定为准；`deliver` 和 `to-tickets` 只补充结论变化后如何更新产物。访谈中的文档记录是已有授权下的动作，不代表切换阶段。

## 技能与调用策略

调用方向为 `grill-me → grilling`；`grill-with-docs → grilling / domain-modeling`。`grilling` 不反向调用入口，记录术语不需要重新开启一轮访谈。

本 PR 为 `grill-me` 和 `grill-with-docs` **新增** `agents/openai.yaml`；基线已有 `implement` 和 `to-tickets` 的同类配置。四个入口在 Codex 中均为显式调用；普通工作不因为需要规划就自动调用显式入口。两个 grill 入口保留原 frontmatter，是为了兼容读取该字段的其他宿主，不代替 Codex 的调用策略。

`software-design` 形成或调整方案，交付推荐方案、依据和必要边界；`design-review` 检查已有方案，交付有证据的问题与结论。保留这些结果标准，但去掉旧版的单向抽象门槛、固定概念分类和理论必读流程。增加和减少抽象都依据实际成本判断，不新增共享理论层，也不把切换技能等同于独立审查。

迁移计划区分最终状态与过渡状态；设计、拆分与评审对兼容、事实归属、验证和退出条件使用一致标准。临时适配本身不是缺陷，不能安全共存时才要求协调修改。

### 名称兼容的范围

只对 `design-before-coding → software-design` 这次更名不提供旧名包装，避免继续暴露误导性的时序入口。基线已有的 `implement → deliver` 兼容入口暂时保留，避免本 PR 同时增加另一项调用方式变更；这不是“所有包装必须删除”的通用标准。后续确无使用需求时可单独删除。

旧名是否从安装环境清除，受 manifest 与目标目录范围限制，见 [安装与更名说明](../README.md#旧设计技能更名)。不推定用户本机已安装了哪份配置。

## 相对基线的其他变化与保留项

`git-commit` 改为项目已有规范优先，个人格式作为默认值。`video-summary` 保留工具知识，取消强制读取登录态的顺序，在已有授权内保持探测与下载认证参数一致。

资金执行正式启用前**必须完成可验证的端到端测试**、局部成功不能代替整体可用的底线不降低；新增明确环境和授权范围、模拟与真实执行分开说明的限定，测试通过不自动授权真实操作。

安装脚本保持不变：仍采用独立目录复制，拒绝符号链接形式的目标 `skills/` 根目录，只依据 manifest 清理过期技能。本 PR 补全这些安装边界的文档与自动测试，不扩大删除权限。

`project-conventions` 及 Python 约定、`domain-modeling` 及格式、`implement` 兼容入口、NCM 技能及脚本保持基线内容；设计与评审技能则属于本 PR 的重写范围。

### 旧参考资料

最终差异直接删除基线的八份设计参考文件，不保留 archive。原文在基线的 `skills/design-before-coding/references/` 和 `skills/design-review/references/` 中；保留该基线历史的克隆可按原路径读取，例如：

```bash
git show 695f8add8dd31827ecc874ade2c64d9ba9b539f1:skills/design-before-coding/references/core-principles.md
```

PR 中间曾新增后删除的归档 README 不是基线资料，也不承诺将它保留在 squash 合并后的主线历史中。删除参考资料是取消默认加载一套通用方法论，不是否定其中所有设计知识；有具体任务需要时可引用适用的知识，而不是整套恢复。

## 验证与后续维护

[安装契约测试](../tests/test_install_contract.py) 检查可确定的脚本行为；[行为回归场景](prompt-evaluation.md) 仍需在真实 Codex 中运行。两类验证分开报告，不把文本、语法或脚本测试当作模型行为改善的证据。

模型升级或调整规则时，用相同项目快照比较必要上下文基线、旧配置和新配置。访谈看模糊消除和遗漏发现，文档看忠实记录，开发看正确性、验证、范围控制与执行成本。失败先保存为案例；有稳定收益的规则才保留，只适用局部的规则下移，无收益的补丁删除。

## 配置依据

- [Codex skills](https://developers.openai.com/codex/skills)：`agents/openai.yaml` 中的 `policy.allow_implicit_invocation` 控制隐式调用，不是权限隔离。
- [Claude Code skills](https://code.claude.com/docs/en/skills)：`SKILL.md` frontmatter 中的 `disable-model-invocation` 控制该宿主的自动调用。
