# 轻量实验记录

供受委托评估本库的人或 Agent 使用。这里只为正在调整的行为组保存记录，不给全部规则建台账，也不进入运行时 AGENTS.md。当前没有模型行为实验报告；本文件是记录约定，不是通过结果或自动 runner。

实际开展比较时，每个主题使用 `YYYY-MM-DD-主题.md`，可在同一报告中记录多套配置与重复运行。受阻未运行也写明原因；不要将“未运行”和有效实验中的“未观察到差异”混为一谈。记录只追加有依据的结论，不要求每个普通代码任务填写。

## 有效配置快照

保留足以识别或重建本次输入的材料，不把本机目录统计当全局真相：

| 层次 | 最少记录 |
| --- | --- |
| 运行环境 | 日期、宿主及版本、模型 ID 与可见推理配置、preset、项目提交/初始快照、工作目录作用域、有效全局/项目指令、工具及权限配置 |
| 解析结果 | 本次使用的主/子 Agent 作用域，实际可见技能及最终来源/provider、版本或内容哈希、调用策略；观察不到的同名候选或其他来源标未知 |
| 实际执行 | 真正加载的技能及内容版本、原始输入与回答、工具动作、阶段产物和独立验收证据；配置变化时记录变更点 |

只覆盖测试会使用的作用域；受控隔离环境也可作为明确边界的基线。比较真实生产组合时，不能仅凭扫描 `~/.agents/skills` 推定全部有效来源。版本未暴露就写未暴露，不猜测。

原始私有日志保存在受控位置，仓库只提交脱敏摘要和可授权访问的证据引用；不提交凭据、真实签名请求、私有业务数据或敏感本机路径。哈希帮助识别版本，不代替可供授权复核的源材料。

## 报告结构

以下为可裁剪的填写结构，不是一次已经发生的实验：

```markdown
# 日期 / 行为组

研究问题及来源：用户决定、失败会话或 issue。
性质：用户偏好 / 授权要求 / 真实性要求 / 项目事实 / 模型补丁，可混合。
本次只改变：具体提醒、技能配置或版本；其他保持条件。
配置快照与证据位置：分别列宿主、模型及有效输入，不把两者混作一个变量。
选取案例与判定：引用案例 ID，列明重复次数和裁判方式，运行前确定。

| 案例 ID | 匿名配置 | 轮次 | 通过/失败/无法判断 | 证据及原因 |
| --- | --- | --- | --- | --- |

观察：改进、退化或本次未观察到差异；未运行的部分及原因。
局限：缺失来源、覆盖范围、样本量或无法排除的共同指令。
决定：保留 / 精简 / 待复验，以及证据能支持的范围。
```

结论与决定分开。删除一处措辞后无差异，可能是其他上下文仍表达同一要求，不证明模型已内化；可以据有界证据作有界决定，但不能取消仍有效的用户偏好与授权约定。

评估范围对应实际支持范围：共享变更检查实际使用的 Codex 与 DSH 组合；宿主专属适配验证其目标与相关兼容性。不设“至少两个模型才能退役”的通用门槛，不把少量全通过当成安全保证。

费用与上下文影响分开记录。有 usage 时分别记录输入、缓存输入和输出；字符数只能作规模指标，不能直接换成 token 或费用。目录没有重复追加，不代表历史内容只计费一次，也不保证后续缓存命中；缺少 usage 时不推算节省金额。
